# Documentation

Four kinds of document, each answering a different question. The split exists so that a reader — or
an agent — loads the one page that matters rather than everything.

| Directory | Answers | Read it when |
|---|---|---|
| [principles/](principles/README.md) | *What must be true, and why* | A rule failed and you want to know what it protects |
| [adr/](adr/README.md) | *Why we chose this* | Something looks wrong and you are about to change it |
| [guides/](guides/README.md) | *How to do this job here* | You are doing the job |
| [use-cases/](use-cases/) | *What this operation is supposed to do* | Changing behaviour, or reading a `@UseCase(id = …)` |
| [reference/](reference/) | *Lookup* | You need the layout, the banned list, or the principle map |
| [exec-plans/](exec-plans/) | *What is in flight, and what we owe* | Planning, or wondering why something is half-done |

## The rules that keep this honest

Documentation decays when nothing depends on it. Three things depend on this tree:

- **Every path reference must resolve.** `tools/check-doc-links.sh` fails the build on a broken
  pointer. Code-fenced examples are exempt, so illustrative snippets can name hypothetical files.
- **Every claimed rule must exist.** `tools/check-rule-references.sh` fails the build when a
  principle names an enforcing rule that is not implemented. A principle that promises enforcement
  it does not have is worse than one that admits it relies on review.
- **Every `@UseCase(id)`, `@ImplementsPrinciple` and `@Adr` in code must resolve to a document.**
  Checked by `TraceabilityRules`.

[reference/principle-map.md](reference/principle-map.md) is generated by `tools/principle-map.sh`
and answers "what actually implements P-071?" from the code rather than from memory.

## Adding a document

- A **principle** when a rule should apply everywhere and outlive the current code. Give it the next
  free number in its band, and add an entry to `principles/README.md`.
- An **ADR** when a decision has a real alternative someone will otherwise re-litigate. Copy
  `adr/0000-template.md`. Reference it from the code with `@Adr` so the reasoning is reachable from
  the thing it explains.
- A **guide** when the same task is done repeatedly and has a right way here.
- Nothing at all, when the code can say it instead. Prefer a rule over a paragraph: a rule nobody
  checks decays silently, and a paragraph nobody reads was never a rule.
